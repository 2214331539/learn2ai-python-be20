# 作业十 · 测试与质量（S6·重点）

对应 [模块 9 · 测试与质量](../../materials/09-testing/README.md)，项目阶段 **S6**。本作业训练一项关键判断力：**识破"假通过"的测试**。

## 你要做的事

1. 用 **pytest** 为关键端点写测试，覆盖：创建成功、查询、**校验失败(422)**、**未认证(401)/越权(403)**、**找不到(404)** 等路径（不要只测快乐路径）。
2. 用 **fixture** 做隔离（例如内存 SQLite + TestClient），保证每个测试独立、可重复。
3. **埋 bug 检验**：故意在业务代码里改错一处（例如创建时漏设默认值、授权判断写反），重跑测试，确认测试**变红**——抓不到的测试就是无效测试。把这次实验过程写进 README。
4. 接入 **ruff + mypy**，修掉报告的问题（**不许用 `# noqa` / `# type: ignore` 掩盖**）。

## 提交内容

放在 `work/<你的用户UUID>/8ceaebd6-99f8-44db-9b54-65108949e154/`：

- `tests/`、`conftest.py`、`README.md`（含"埋 bug 实验记录" + ruff/mypy 结果）；
- AI 协作记录。

> 成果由应用用你的 GitHub 身份提交并请求分享确认，你不需要自己 `git push`。

## AI 协作记录（必写）

见 [AI 协作检查清单](../../materials/_shared/ai-collaboration-checklist.md)。特别说明：AI 写的测试里，有没有"断言太宽松、怎么写都过"的？你是怎么加严的？

## 评分标准（100 分）

- 测试覆盖错误/边界路径，断言严格（35 分）
- fixture 隔离得当、测试可独立重复（15 分）
- 埋 bug 实验证明测试有效（20 分）
- ruff + mypy 通过且未用 ignore 掩盖（15 分）
- AI 协作记录真实具体（15 分）

## 提示

- 覆盖率是参考不是目标：100% 覆盖率也可能全是无效断言。
- 检验测试质量最硬的办法，就是故意弄坏代码看测试会不会红。
