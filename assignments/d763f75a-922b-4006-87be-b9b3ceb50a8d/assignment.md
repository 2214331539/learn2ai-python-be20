# 作业三 · 用 dataclass、类型注解与装饰器重构

对应 [模块 2 · 函数式与面向对象](../../materials/02-functions-oop/README.md)。

本作业训练一项关键能力：**让 AI 重构你的代码，而你能判断重构是真的变好还是只是变花哨。**

## 背景

你的 `taskbox.py` 已经能用，但数据结构可能还是裸 `dict`、函数也缺类型注解。这次把它重构到更清晰、更自文档化的形态。

## 你要做的事

1. **用 `@dataclass` + 完整类型注解**重写 `Task`（和 `Bookmark`，如果你已加入），正确处理可变默认值（`field(default_factory=...)`）。
2. **写一个有实际用途的装饰器**，例如 `@log_call` 记录每次操作，或 `@timer` 计时；必须使用 `functools.wraps`。
3. **AI 重构 + 你当裁判**：让 AI 对你的脚本做一次整体重构，然后在 README 中记录——你**接受**了哪些改动、**否决**了哪些、分别为什么。至少要有一处你否决或修改 AI 建议的例子。

## 提交内容

放在 `work/<你的用户UUID>/d763f75a-922b-4006-87be-b9b3ceb50a8d/`：

- 重构后的代码、`README.md`（含"重构评判"小节 + 运行说明）；
- AI 协作记录。

> 成果由应用用你的 GitHub 身份提交并请求分享确认，你不需要自己 `git push`。

## AI 协作记录（必写）

见 [AI 协作检查清单](../../materials/_shared/ai-collaboration-checklist.md)。本次重点是"重构评判"：说清你为什么认为某处重构更好 / 更差。

## 评分标准（100 分）

- dataclass + 类型注解正确、无可变默认值坑（30 分）
- 装饰器可用且使用 `functools.wraps`（20 分）
- "重构评判"有真实取舍、能讲出理由（30 分）
- AI 协作记录真实具体（20 分）

## 提示

- 重构不是越简洁越好，也不是越"高级"越好。可读性、可测试性才是标准。
