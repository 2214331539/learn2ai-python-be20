## 重构实现

### 数据模型与类型

```python
@dataclass
class Task:
    id: int
    title: str
    done: bool = False
    tags: list[str] = field(default_factory=list)
```

`dataclass` 自动生成初始化、表示和相等比较方法，使用 `task.title` 等明确字段替代字典字符串键。`field(default_factory=list)` 为每个任务创建独立标签列表，避免跨任务共享可变状态。

所有业务函数、CLI 和装饰器都标注参数与返回类型；`ParamSpec`/`TypeVar` 用于保留装饰器前后的参数类型和返回类型。类型注解不会自动做运行时校验，空标题仍由函数显式检查。

`add_task(tasks, title, tags=None)` 可在 Python 调用中添加标签，函数将标签复制到任务自己的列表，调用者随后修改原列表不会影响任务。CLI 本轮保持原有交互，不增加标签输入步骤。

### 有实际用途的装饰器

`@log_call` 用于新增和完成任务，记录操作开始、成功或失败，方便区分正常操作和输入导致的失败。`@wraps(function)` 保留函数名、文档字符串、注解和 `__wrapped__`，`inspect.signature` 可以继续看到原函数签名。

装饰器返回原函数的结果；发生异常时记录失败并重新抛出，由 CLI 分别处理 `TaskNotFound` 和 `ValueError`。日志仅记录函数名与状态，不记录标题或完整参数；导入模块时不配置全局日志，只有直接运行脚本才调用 `basicConfig`。

## 重构评判

以下是 **AI 实施取舍及供学员复核的判断依据**，不是用户已经作出的个人评价。

| 改动或候选方案 | AI 的实施选择 | 理由 |
| --- | --- | --- |
| 字典改为 `Task` dataclass | 采用 | 字段集中定义，属性访问更清楚，减少重复键名 |
| 标签使用 `default_factory=list`，传入标签复制后保存 | 采用 | 同时避免实例间共享和调用方列表别名导致的意外修改 |
| 用 `@wraps` 的日志装饰器 | 采用 | 复用操作日志，又保留调试所需元信息 |
| 捕获所有异常后 `return None`，让程序继续 | 否决该候选写法；实际实现为记录后 `raise` | 返回 `None` 会掩盖失败并破坏返回类型，调用方可能误判为成功 |
| 将 CLI 全部移入装饰器，或额外加入数据库/框架 | 不采用 | 交互会与业务耦合，且超出本次重构范围；独立的业务函数更容易验证 |

可核验的具体取舍是 `log_call` 的失败分支：它确实使用 `raise` 保留异常，测试验证原异常对象不变且没有“完成”日志。上述否决由 AI 自查提出；本轮用户没有反馈个人接受/否决意见。
