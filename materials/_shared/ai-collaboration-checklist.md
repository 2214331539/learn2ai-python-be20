# AI 协作检查清单

> 这是全课贯穿使用的工具。每次让 AI 帮你写后端代码时，按这份清单走一遍。
> 核心原则：**AI 负责产出草稿，你负责判断与把关。责任永远在你这边。**

## 一、提出需求前（想清楚再开口）

把任务对 AI 描述清楚，至少说明这 5 件事：

- [ ] **目标**：这段代码要做什么？（一句话）
- [ ] **输入 / 输出**：数据从哪来、长什么样；期望返回什么。
- [ ] **约束**：用哪个框架/库版本、性能要求、不能引入哪些依赖。
- [ ] **边界条件**：空值、超大输入、并发、错误时该怎么办。
- [ ] **上下文**：贴上相关的已有代码、数据模型、报错信息，而不是让它猜。

> 反例："帮我写个用户登录。"
> 正例："用 FastAPI + SQLAlchemy 2.x 写一个 POST /login，接收 email 和 password，
> 校验数据库里的用户，密码用 bcrypt 比对，成功返回 JWT，失败返回 401。这是我的 User 模型：……"

## 二、拿到代码后（先读后跑）

**绝不要在没读懂之前就运行或提交 AI 的代码。** 逐项核对：

- [ ] 我能逐行解释这段代码在做什么吗？不能解释的地方就是风险点。
- [ ] 它用到的库/函数/参数**真实存在**吗？（AI 会编造 API）
- [ ] 依赖是否最小？有没有为了小事引入大库？
- [ ] 错误处理在哪？异常会不会被悄悄吞掉？
- [ ] 边界条件（空、超长、负数、并发）处理了吗？
- [ ] 有没有把密钥、密码、token 写死在代码里？
- [ ] 日志里会不会打印出敏感信息？

## 三、安全红线（后端尤其要盯）

- [ ] **SQL/命令注入**：有没有用字符串拼接 SQL / 拼接 shell 命令？必须参数化。
- [ ] **越权**：接口有没有校验"这个用户能不能操作这条数据"，而不只是"登录了没"。
- [ ] **密码**：是否使用成熟哈希（bcrypt/argon2），而不是明文或 md5。
- [ ] **输入校验**：外部输入是否经过 Pydantic/schema 校验再使用。
- [ ] **密钥管理**：密钥是否从环境变量读取，而非硬编码进仓库。

## 四、绝不全权交给 AI 的事

- 生产数据库的删除/迁移操作
- 密钥、凭据、权限边界的设计
- 涉及钱、隐私数据、对外发布的最终决策

这些 AI 可以给建议，但**必须由你审查后手动把关**。

## 五、调试协作

遇到报错时，给 AI 提供：**完整报错 + 栈追踪 + 相关代码 + 你已经试过什么**。
不要只贴一行"报错了"，也不要盲目复制它给的"换个写法"——先问清"为什么会错"。

## 六、作业中必须附上的"协作记录"

每份作业请附一小段说明（3–6 句即可）：

1. 我让 AI 做了什么（关键提示）。
2. AI 给的方案我**改了/否决了**哪些地方，为什么。
3. 我做了哪些验证（跑了什么、测了什么边界）。

> 本课考核的是**你的判断力**，不是代码出自谁之手。坦诚写协作记录不会扣分，隐瞒才会。
